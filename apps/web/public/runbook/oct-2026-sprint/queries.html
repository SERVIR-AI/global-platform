Every question and request carries the use case it serves; the two pack demos in the Wed AM sheet are tagged as outside the three.

How to ask. Name the place as a map labels it (a district, canton, reserve, municipality); say which boundary if the name matches several; name a dataset by its common name when you want a particular one; one place and one or two datasets per question; never a whole country. A question that times out keeps running on the server, so wait a minute before asking again.

Data standardization: talking points

  • The manifest is the standard: every contribution, of any kind, declares the same facts (title, description, source, licence, vintage, countries, usage notes) plus the contract the file is checked against (legend or units, dtype, nodata) or the field that names its features.
  • The platform prepares on the way in, so hubs bring data as it is: loose shapefile parts, a WFS, a tile zip, a 1 m GeoPackage, a PDF. Clip, mosaic, rasterise, recode, assemble: each step is recorded with hashes.
  • The gate refuses silence and guesses: no licence, an unmapped class value, a picture of a map. A decline names the field or lists every class value found, so the fix is in the decline.
  • Editions change their classes: the 2024 official Ecuadorian map has no mangrove class at level 2. The landing note states the values mapped; read it before asking about change. The gate reports it; it does not refuse it.
  • Every answer carries its receipt: sources with vintage and validation, the hash of the text, the gaps declared. Defaults are labelled defaults; an accuracy nobody declared is never invented.

Roles

  • Contributor (a hub scientist): brings the link and declares the facts; the gate does the rest; withdraws when wrong.
  • Reviewer: approves or holds; the sprint host auto-approves and the record says so.
  • Analyst: asks by name in Claude Desktop and reads the receipt; never the model’s arithmetic.
  • Builder: builds apps in Claude Code on the platform’s embeds and design tokens; never computes.
  • Platform maintainer: owns the seams and registries; a capability is built once for every pack, never as a branch on a pack’s name.

What every contribution declares

  • title, description, source, licence (or “unstated”, never silence), vintage, countries, usage notes
  • raster: legend (class number to label) or units; declared dtype, valid range, nodata; clip when the file is large; stack and year for a series
  • vector: the name field that makes each feature an area; optionally a group field for a breakdown
  • feed: the records path, the fields and the as-of field; validation, residency and cadence
  • document: the file and what it is; the platform indexes passages for citation
  • table: the columns and, for a factor table, the class it applies to and the unit
When a contribution is declined, read the decline: it names the missing field, lists every class value the layer holds, or states the size and the clip to give. Resubmit with that; nothing else changes.
